=== headings | Headings
A heading names a section. Put `#` at the start of a line, then a **space**, then the words. More `#` signs make a smaller heading:

```
# The biggest - the title of the whole file
## A section
### A smaller part of a section
```

Instruction files use one `#` for the assistant's name and `##` for each section. Watch the space: `#Trip Helper` stays plain text, `# Trip Helper` becomes a heading.
--- task
Write a level-1 heading that says **Trip Helper**. Under it, write a level-2 heading that says **What you are for**.
--- start
--- checks
A level-1 heading that says "Trip Helper"        @ heading1 is Trip Helper
A level-2 heading that says "What you are for"   @ heading2 is What you are for

=== paragraphs | Paragraphs
Lines that sit next to each other run together into one paragraph. To start a new paragraph, leave a **blank line**:

```
This is the first paragraph.
It is still the first paragraph.

This is a second paragraph, because of the blank line above it.
```

An AI reads your file either way, but people read it too - including you, in three weeks, trying to remember what you meant.
--- task
Under the heading, write **two short paragraphs** about what Trip Helper does, with a blank line between them.
--- start
# Trip Helper

## What you are for
--- checks
Two separate paragraphs                     @ paragraphs at least 2
The "Trip Helper" heading is still there    @ heading1 is Trip Helper

=== emphasis | Bold and italic
Two stars on each side make **bold**. One star on each side makes *italic*.

```
**This rule matters most.**
*This is a gentle suggestion.*
```

In an instruction file, bold marks the rule that must not be missed. Use it sparingly - if everything is bold, nothing is.
--- task
Under the **Tone** heading, write one sentence with a **bold** phrase and another with an *italic* phrase.
--- start
## Tone
--- checks
Something in bold      @ bold at least 1
Something in italic    @ italic at least 1

=== bullets | Bullet lists
Start a line with a dash and a space to make a bullet. Each bullet is one rule:

```
- Keep every answer under 150 words.
- Ask before booking anything.
```

Short, separate rules are easier for an AI to follow - and easier for you to check - than one long paragraph that hides three rules inside it.
--- task
Under **Never**, write at least **three bullets** - things Trip Helper must never do.
--- start
## Never
--- checks
A level-2 heading that says "Never"    @ heading2 is Never
At least three bullets                 @ bullets at least 3

=== numbers | Numbered lists
A number and a period make a numbered list. Numbers mean *order* - this happens first, then this:

```
1. Ask where they are going.
2. Ask how many days.
3. Suggest a plan for each day.
```

Bullets are for rules. Numbers are for steps. That difference is the start of turning a prompt into a workflow, which is Module 2.
--- task
Under **Steps**, write at least **three numbered steps** Trip Helper follows to plan a day out.
--- start
## Steps
--- checks
A level-2 heading that says "Steps"    @ heading2 is Steps
At least three numbered steps          @ numbers at least 3

=== links | Links
Square brackets hold the words people see. Round brackets right after hold the web address:

```
Check the [park hours](https://www.nps.gov) before you go.
```

In an instruction file, a link points the AI at a source you trust, instead of whatever it happens to remember.
--- task
Write a sentence that links the words **park hours** to `https://www.nps.gov`.
--- start
--- checks
A link to https://www.nps.gov    @ link to https://www.nps.gov
The words "park hours"           @ text has park hours

=== exact | Exact words
Backticks - the key usually under Esc, top left - mark text that must be used **exactly**, letter for letter:

```
Start every plan with `PLAN:` on its own line.
```

This is how you tell an AI "these exact characters, please", which matters the moment another tool has to read what it writes.
--- task
Write a rule telling Trip Helper to start every answer with the exact word `PLAN:`. Put `PLAN:` in backticks.
--- start
--- checks
PLAN: inside backticks    @ code is PLAN:

=== codeblocks | Exact layouts
Three backticks on a line of their own start a block. Three more end it. Everything in between is kept exactly as typed - spacing, line breaks, all of it:

````
```
Day 1:
Day 2:
```
````

Use this to give an AI a layout to fill in. It copies the shape, and anything downstream knows where to look.
--- task
Write a code block holding a three-line layout: **Morning:**, **Afternoon:** and **Evening:**, one per line.
--- start
--- checks
A code block                  @ code blocks at least 1
It has a line for Morning:    @ text has Morning:
It has a line for Evening:    @ text has Evening:

=== tables | Tables
Pipes `|` make columns. The first row is the header. The row of dashes underneath it tells markdown the header has ended:

```
| Weather | Plan |
|---|---|
| Sunny | The lake trail |
| Rain | The museum |
```

Tables are the quickest way to give an AI a decision rule - *if this, then that* - in a form you can check at a glance.
--- task
The header row is started for you. Add the row of dashes, then **at least two rows** of your own.
--- start
| Weather | Plan |
--- checks
Two columns               @ table columns at least 2
At least two rows         @ table rows at least 2
