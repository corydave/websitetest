1. What an extension actually is

Here is the whole idea - an extension is a folder with software that runs on the web pages you visit.

The folder holds ordinary HTML, CSS and JavaScript - the same three things you have been writing since the first week. Nothing in it is a new language. There is a file, a "note", that is a file called manifest.json, and it tells Chrome three things: what this extension is called, what it wants to touch, and which file does the touching.

That is it.

The ad blocker you installed is a folder with a note on the front. So is the password manager. So is the thing you are about to build.

The reason extensions feel like a different category of software is that they can do one thing your apps could not: run inside a page somebody else wrote. Everything you have made so far lived at its own address and minded its own business. An extension reaches into Wikipedia, or your email, or this handout, and changes what you see.

Here is that, happening. The page below is an ordinary web page with a button. Click Swap the words and watch the text change. Then change what it swaps and run it again.

One of them did not change. Look at the last sentence: nobody has ever lost anything to the cloud. Now look at the code - in the paragraph, the words the and cloud have a line break between them. The computer is looking for the cloud with a space in the middle, and what is actually there is the, then a new line, then cloud. Not a match.

Nothing is broken. The code did exactly what it was told. That story is what most of programming is! Try joining those two lines in the code and pressing the button again.

2. The guts: what is in the folder

Every extension you build this week has the same shape. A folder, a manifest, and one file per job.

Which files you need depends on what the extension does:

If your extension... it needs
replaces the new tab page an HTML file and its .js file
changes pages you visit a content script - a .js file Chrome injects into the page
shows a small panel when you click the icon an HTML file and usually a .js file
sits in a panel beside the page an HTML file, a .js file, and a service worker

Two of those words are new and both are plainer than they sound.

A content script is just a JavaScript file that Chrome drops into somebody else's page, where it can see and change everything on that page. The demo above is a content script that has not been put in a folder yet.

A service worker is a small file that runs in the background, outside any page. Labs 3 and 4 each have one, a few lines long: in lab 3 it builds the right-click menu, and in lab 4 it decides what happens when the toolbar icon is clicked.

Why some labs need more files. Not because they are bigger. It is because part of your code runs in the background or in your own panel, and part of it runs inside someone else's page, and those parts have to be in different files so Chrome knows which is which.

Two rules your apps never had

No script written inside the HTML. Every app so far kept its JavaScript in a <script> block inside the one file. In an extension, Chrome refuses to run that. Scripts go in their own .js files, and the HTML points at them with one line: <script src="newtab.js"></script>. The reason is safety: Chrome only runs code it can find sitting in a file in your folder, so nothing can sneak in disguised as text on a page.

No libraries from the web. Last chapter you borrowed code from a CDN with one line. An extension can't do that either - Chrome only runs code that is inside the folder. If you ever truly need a library in an extension, you download that exact version into the folder. The background check from last chapter still applies, and now the copy is yours to keep up to date.

Both rules are in the extension specification you will paste this week, so the AI should follow them. When it doesn't, the Developer Console says Refused to execute inline script or Refused to load the script, and now you know what that means.

3. The note on the front

Here is a complete, real manifest.json. This is lab 1's, entire:

{
  "manifest_version": 3,
  "name": "My Launch Pad",
  "version": "1.0",
  "description": "My own new tab page.",
  "chrome_url_overrides": { "newtab": "newtab.html" }
}

Six lines. manifest_version says which generation of the rules you are using (3 is current). name, version and description are what shows on the extensions page. The last line is the only interesting one, and it says: when the person opens a new tab, show them my file instead.

This file is JSON, not JavaScript. They look almost the same and they are not the same. So here's the difference:

  • No comments. Not //, not /* */. The AI writes comments by habit and this course has been telling it to. In a manifest they break everything.
  • No trailing comma. A comma after the last item in a list is fine in JavaScript and illegal here.
  • Double quotes only. Not single quotes.

Get one of those wrong and Chrome does not load a broken extension - it refuses the whole thing and shows a red error card. Which is actually good news: you find out immediately, not later.

If you want to check a manifest before loading it, paste it into the AI and ask "is this valid JSON?". It is very good at this and it takes five seconds.

4. Yours, on this computer

Normally an extension comes from the Chrome Web Store. You search, you click Add, and Chrome keeps it updated and carries it to your other computers when you sign in.

That is not what we are doing. This week you load your extensions unpacked, which means: here is a folder on my hard drive, run it. You turn on Developer mode, click Load unpacked, pick the folder, and it is live.

That difference has four consequences worth knowing up front, because every one of them will otherwise feel like a bug:

  • It only exists on this computer. Not on your phone, not on the lab machine, not in a different browser.
  • It does not sync. Signing into Chrome somewhere else will not bring it.
  • It does not update itself, which is fine, because you are the one changing it.
  • It breaks if the folder moves. Chrome remembers the path, not the files. Move or rename the folder and the extension goes dead. Pick a home for it now.

Putting one in the actual Web Store means a five dollar developer account and a review queue, and it is not worth it for a tool you built for yourself. That is genuinely what most extensions are: somebody solved their own problem on their own computer. You are about to do the same thing.

5. What you are agreeing to

When you install an extension from the store, a box appears that says something like:

Read and change all your data on all websites

Almost everybody clicks past it. Here is what it actually means, now that you know what is in the folder: this folder contains a content script, and Chrome will drop it into every page you open, where it can see everything on that page and change anything it likes.

Everything. Your email while it is on screen. Your bank balance while it is on screen. What you type into a form, before you press send.

That is not a reason to panic about extensions. It is a reason to know which ones you have given that to, and why. A password manager needs to see the login box. A coupon finder does not need to see your medical portal, but plenty of them ask for it anyway, because asking for everything is easier than asking for what you need.

This week you write that sentence about your own code. In lab 2 you will ask for one website, and then widen it, and see the sentence on your own extension change as you do.

The habit worth keeping. The extension spec block you will paste this week has a line in it that the others do not: request the narrowest permissions that will do the job, and say in a comment why each one is needed. Professionals call this least privilege. It is the same instinct as not giving a house key to somebody who only needs to water the plants once.

6. Taking it back

This is the most useful thing in this reading and hardly anybody knows it.

You can change what an extension is allowed to reach, after you installed it, without uninstalling it.

Right-click any extension's icon in the toolbar. There is a menu item called This can read and change site data, and under it, three choices:

Choice What it means
When you click the extension It can do nothing until you click it. Nothing in the background, ever.
On specific sites It works on the sites you name and is blind everywhere else.
On all sites What it asked for.

Most extensions will work perfectly well on When you click the extension, and most people never try. A coupon finder does not need to watch you read the news. Try it: the worst case is that something stops working and you put it back.

The fuller version lives at chrome://extensions - type that into the address bar. Every extension you have, what it can reach, an on/off switch, and a Remove button. It is worth five minutes right now, before you build anything. Most people find at least one thing they do not remember installing.

You install a tool that highlights spelling mistakes as you type. It asks to read and change your data on all websites. You only ever want it on one forum.

Install it, then right-click its icon and set site access to On specific sites, naming the forum. It keeps working where you want it and is blind everywhere else - including on your email, which it was about to be able to read.

7. What an extension cannot do

Some limits will save you a confusing afternoon.

  • It cannot run on Chrome's own pages. chrome://extensions, the new tab page, the settings screens. Chrome protects these from extensions, including yours.
  • It cannot run on the Chrome Web Store. Same reason.
  • It cannot run on files opened from your own computer - anything whose address starts with file:// - unless you turn on a specific setting. This one matters this week: to try your extension on your own apps, use their real web address, the github.io one from chapter 3, not the file on your desktop. You have had a live site since chapter 3 and this is one more reason it was worth doing.
  • It cannot load code from the web. No CDN libraries - see the two rules in section 2.
  • It cannot be sent to somebody as a link. Everything you made in chapter 4 could be texted to a friend. This cannot. To give somebody an unpacked extension you have to give them the folder and talk them through Developer mode, which is a lot to ask. These are tools for the person who made them, and that is a real difference from everything else in this course.
  • It is Chrome and Edge only, here. Edge is built on the same engine and takes the same folder unchanged. Safari needs a whole different toolchain. Firefox is close but not identical.

8. Four real ones

Extensions are at their best when they fix something small that annoys one person every single day. A few that exist because somebody got irritated enough:

  • A new tab page that is actually useful. The default one is a search box and some thumbnails nobody chose. Replacing it with your own links takes twenty minutes and you will look at it dozens of times a day. This is lab 1.
  • A page that rearranges itself. A site you use constantly puts the thing you need at the bottom, or in alphabetical order when you want it grouped. A content script can move it. This is lab 2's technique aimed at something useful instead of something funny.
  • A text shortcut. Anything you retype more than twice a week - an email signature, a standard reply, an address, a block of placeholder text - put into any box on any site with a right-click. This is lab 3.
  • A reader that pulls the facts out of a wall of text. Paste in a messy email and have it find the dates, names and amounts. This is lab 3's shape, pointed at a real job.

Your instructor has built several of these and shows the real ones in this week's video, including what they looked like when they were broken.

9. Where it goes wrong

In rough order of how often it will happen to you.

You changed the code and nothing happened. There are two reloads, and you usually need both. First reload the extension: go to chrome://extensions and click the circular arrow on your extension's card. Then reload the web page itself. Changing a content script and only refreshing the page does nothing, because the old script is still the one Chrome has.

Chrome shows a red error card and refuses to load it. Almost always the manifest: a comment, a trailing comma, or a single quote. Read the error, fix that one character, press reload.

Chrome says the manifest is missing and you can see it right there. The file is probably called manifest.json.txt. Your text editor added .txt when you saved. This is the chapter 1 problem again and it will not be the last time.

Load unpacked did not work. You pick the folder that contains manifest.json. Not the manifest file itself, and not the folder above it.

It works on one site and not another. Check the three things in section 7 first - Chrome pages, the Web Store and file:// addresses are all off limits.

Your extension is still running and you forgot. Especially lab 2. If a website starts looking strange next month, chrome://extensions is the first place to look. Switch off what you are not using.

10. Cheat sheet

Thing What it is
extension a folder of ordinary web files, with a note on the front
manifest.json the note. Required, always named exactly this, and it is JSON, not JavaScript
unpacked loaded from a folder on your computer instead of the Web Store. This machine only
Developer mode the switch on chrome://extensions that lets you load unpacked folders
content script a JavaScript file Chrome drops into somebody else's page
service worker a small background file that is not part of any page
popup the little panel that appears when you click the toolbar icon
side panel a panel that stays open beside the page while you browse
permission what the extension asked to be allowed to do
site access what it is allowed to reach right now - and you can change this whenever you like

Three things to remember when something is broken: reload the extension, then reload the page. Check the manifest for a comma. Check the file is not called .json.txt. And if the console says Refused to, a script is inside the HTML or coming from the web.

One thing to do today, even if you build nothing: open chrome://extensions and look at what you have already given permission to.
