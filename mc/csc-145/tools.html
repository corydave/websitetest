Prompts worth keeping

The specification

The block you paste at the end of every prompt that asks for an app. It tells the AI how to build things for this course. You are not expected to understand every line - one line gets explained per chapter, as the course runs into the reason for it.

Build it to this specification:

# SPECIFICATIONS

* Everything in one single HTML file - HTML, CSS, and JavaScript together
* No build tools - no React, Vue, or anything requiring npm
* CDN libraries are fine if they help
* Use vanilla JavaScript only
* Fully responsive - works on phone, tablet, and desktop
* Fully accessible - semantic HTML, ARIA labels, keyboard navigation
* No data sent to any server - everything runs in the browser only
* Versioning in comments (e.g., // v1.0 - initial build)
* Very descriptive JavaScript comments explaining each code block in plain language

The specification, extension version

Same thing, for the chapter where you build browser extensions. An extension is a folder rather than one file, so one line changes and two are added.

# SPECIFICATIONS - BROWSER EXTENSION

* A Chrome extension using Manifest V3
* As few files as possible - manifest.json, plus one file per job
* No build tools - no React, Vue, or anything requiring npm
* CDN libraries are fine if they help
* Use vanilla JavaScript only
* Fully accessible - semantic HTML, ARIA labels, keyboard navigation
* Versioning in comments (e.g., // v1.0 - initial build)
* Very descriptive JavaScript comments explaining each code block in plain language
* No comments and no trailing commas anywhere in manifest.json - it is JSON, not JavaScript
* Request the narrowest permissions that will do the job, and add a comment saying why each one is needed

The interview prompt

For when you want something built about you and you are not sure how to describe it. Instead of you writing a long prompt, the AI asks you questions one at a time. Paste the specification at the end, where it says to.

Ask me questions, one at a time, until you have enough to build a
personal webpage for me. Ask only one thing at a time, and wait for
my answer before moving to the next.

Make sure you understand: who I am, what I want this page to do for
me, what a visitor should walk away knowing, and what I want to
link to.

Before you build anything, stop and tell me:
  - what you understood
  - exactly which images you'll need, what to name them, and
    which folder to put them in

Then wait for me to say I'm ready.

When something breaks

The single most useful habit in this course, and the one people skip. Do not describe the symptom. Quote the error.

  1. Open the Developer Console - F12, or Cmd + Option + I on a Mac.
  2. Look for red text.
  3. Copy it. All of it, exactly as it appears.
  4. Paste it back to the AI with one sentence about what you were doing.

"It's broken" gets you a guess. The exact red line gets you a fix. The difference is dramatic and it does not stop being true once you are good at this.

Here is the exact error from the console:

[paste the red text]

This happened when I [what you did]. Without fixing anything yet,
tell me what is most likely causing it.

That last line - without fixing anything yet - is worth keeping. It stops the AI rewriting half your file to fix a typo.

ListenMode

Hides the page and says out loud what the keyboard lands on as you press Tab - "Submit, button", or revealingly, "button, with no name." Useful on your own apps, and startling the first time.

Drag the button below onto your bookmarks bar. Do not click it here - it only works once it is a bookmark. Press Ctrl + Shift + B (Cmd + Shift + B on a Mac) if you cannot see your bookmarks bar.

It is a demonstration, not a screen reader. A real one reads your whole computer, has separate modes for reading and for filling things in, and hundreds of commands. This does one slice: it follows the keyboard and tells you what it finds. Enough to show you holes in your own work; not enough to tell you what using a screen reader is really like.
