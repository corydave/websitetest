1. A folder is an address

Last chapter everything went into one folder, vibe-coding, side by side. That worked, and it worked for a reason you probably didn’t notice: every app was a single file that needed nothing else. Nothing had to find anything.

That stops this week. A recipe card needs a photo. A page of pictures needs pictures. A page with a second page needs to know where the second page is. The moment a page needs another file, the question where is it? has to have an answer.

The answer, almost always, is: right here, beside me.

A folder is an address. Everything at the same address can find everything else by name alone. Your page asks for photo.jpg, and the browser looks in the folder the page is in, finds it, and draws it. It does not search your computer. It looks in exactly one place.

That is the same-folder rule, and it is the whole idea of this chapter. One app, one folder, everything the app needs inside it.

2. index.html is the front door

Every app folder gets one file called index.html.

Not because the file has to be called that. Because everything that goes looking inside a folder has agreed to open index.html first, without being told to. Browsers do it. The computers that serve websites do it. Near the end of this course you will write a program that walks through all of your folders, and it will do it too.

One predictable name, so that nothing has to guess.

You are about to have four folders and four files called index.html, and they will not get confused with each other, because the folder is the name now. qr-code/index.html and countdown/index.html are as different as two houses with the same color front door.

Only the front door gets the standard name. Everything else in the folder is called what it is: photo.jpg, notes.html, index-v1.html.

There is a second half to this that you can’t see yet. When these folders go up on the internet in a few weeks, you will be able to hand someone an address with no file name on the end at all - just the folder - and the right page will open anyway. That is this convention paying you back. Today it is tidiness; later it is your web address.

3. Attributes: extra information on a tag

You know tags. <h1>Hello</h1> - two bookends with content between them, and the tags say what the content is.

Some tags need to know more than that. A picture tag needs to know which picture. A link tag needs to know where it goes. That extra information rides inside the opening tag, and it is called an attribute.

An attribute is always the same shape:

name="value"

A name, an equals sign, and a value in quotes. The quotes are part of it, not decoration - they are how the browser knows where the value starts and stops. A tag can carry more than one, separated by spaces:

<img src="photo.jpg" alt="A bowl of soup" />

One tag, two attributes. You have actually seen this already: the QR code app had a <script src="..."> line near the top, and src there means the same thing it is about to mean for pictures - go and fetch this.

4. Pictures: src and alt

<img src="photo.jpg" alt="A bowl of tomato soup with basil on top" />

src is short for source. It is the file name the browser goes looking for, in the same folder as the page.

alt is short for alternative. It is words that stand in for the picture.

alt does three jobs, and it is the most undervalued attribute in HTML:

  • It is what a screen reader says out loud to someone who cannot see the picture.
  • It is what appears on the page when the file is missing.
  • It is what a search engine reads, because a search engine cannot look at a photo either.

Write it as though you were describing the picture to someone over the phone. Not alt="photo", not alt="image1" - those say nothing to anybody. alt="A bowl of tomato soup with basil on top".

Here it is with a file that isn’t there, which is what you get on this page and what you will get the first time you try it for real. Change the words in alt and watch the page change.

That is not an error message. The browser is telling you, politely, I looked for a file with that name and there wasn’t one. When photo.jpg really is sitting beside your page, the photo appears and the alt words go quiet.

We come back to alt in a few chapters and check whether the AI wrote good ones across everything you have built. Spoiler: sometimes it does. Write yours properly now and you will have less to fix then.

5. The slash on the end

Look at that tag again: <img src="photo.jpg" alt="..." />. There is a slash before the closing bracket, and there is no </img> anywhere.

Some tags have nothing to wrap. There is no “content of a picture” to sit between bookends - the picture is the content, and it is named by src. So the tag opens and closes in one move, and the slash is how it says so. You met this last chapter with <br />; it is the same idea with more to carry.

You will also see <img> written with no slash at all, including by the AI. Both work, and browsers have never cared. The slash is a habit worth having anyway, because when you are skimming a file it tells your eye immediately that nothing is coming.

6. Links: href

<a href="notes.html">Read my notes</a>

<a> is a link. It has two parts, and keeping them separate in your head makes links easy forever:

  • href is where it goes. A file name, when the file is beside this one. That part is for the browser.
  • The words between the tags are what the person sees and clicks. That part is for the human.

They are completely independent. You can change the words without touching the destination, and the other way round.

Clicking it here does nothing, because there is no second file in this pretend browser. On your computer there will be, and it will work.

This chapter keeps every link as simple as the one above: a file name, and the file sits beside the page. Links can also point into other folders and out at other websites, and those get a chapter of their own once you have a site big enough to need them.

7. Filenames are exact

This is the section that saves you an evening.

src="photo.jpg" means a file called photo.jpg. It does not mean:

  • Photo.jpg - a capital letter is a different character
  • photo.JPG - so is a capital extension
  • photo.jpeg - same kind of picture, different name
  • photo .jpg - there is a space in there
  • photo copy.jpg - what your computer named it when you duplicated it

Here is the trap. On your own computer you will often get away with the wrong capital letters, because Mac and Windows are usually relaxed about it. That is not a kindness, it is a delayed problem. The internet is not relaxed about it, and in a few chapters the exact file that worked on your desk all semester will stop working, with no error message and no clue why.

So build the habit now, while nothing is at stake: lowercase, hyphens instead of spaces, and type the extension yourself. Then make the code and the file match character for character.

One more that catches people every single time: photos taken on an iPhone are often saved as .HEIC, and browsers mostly cannot show that format at all. It is not a naming problem and renaming it will not help - the file has to be converted to a JPG first.

8. When the picture doesn’t show

You get a broken icon, or an empty box with your alt words in it. The message is always the same: I looked in this folder for that name, and it wasn’t there.

Three things to check, in this order:

  1. Is the file actually in the folder? Not in Downloads. Not still in Photos. In the same folder as the page.
  2. Does the name match exactly? Right-click the broken picture and choose Inspect. The line it highlights has the src in it - that is what the code is asking for. Compare it to the real file, one character at a time.
  3. Can a browser show that format? JPG and PNG, yes. HEIC, no.

Notice what is not on that list: your code. A missing picture is almost never a code problem, which is good news, because it means you can fix it without understanding a single line.

9. When the whole page goes blank

A missing picture is a small failure - one thing is gone and the rest of the page carries on. This one is not small. You change something, refresh, and get a completely white page. No app, no error, nothing.

It is almost always punctuation in a list, and it is almost always a comma.

Why one comma takes out the whole page

When an app keeps its content in a list - the pictures in a slider, the cards in a deck, the questions in a quiz - that list is read by the browser before anything runs. The browser reads it top to bottom and needs every item separated by a comma. If it hits an item where it expected a comma and finds something else, it cannot tell where one item ends and the next begins, so it gives up on the whole file.

Not just that line. The whole file. The page goes white because nothing ever got to run.

It feels wildly out of proportion to a missing comma, and it is. Every person who writes code has lost an evening to this.

How to find it in thirty seconds

  1. Open the Developer Console. This is what it is for, and it is the difference between thirty seconds and an hour.
  2. Read the red line. You are looking for the words SyntaxError and, usually, Unexpected token. Something is in a place the browser did not expect.
  3. Read the number. After the file name there is something like index.html:38. That is the line.
  4. Go to that line - then look at the line above it. The browser reports where it noticed the problem, which is usually one line after where the problem actually is. The line above is the one missing its comma.

The three that cause it

A missing comma. You added an item to the end of a list and the item before it did not have a comma after it, because it used to be last.

{ file: "photo-5.jpg", caption: "The lake" }     <- needs a comma now
{ file: "photo-6.jpg", caption: "The dock" }

An apostrophe inside single quotes. Text wrapped in 'single quotes' ends at the next single quote - and an apostrophe is a single quote. So 'Grandma's kitchen' ends after Grandma, and everything after it is nonsense.

caption: 'Grandma's kitchen'     <- breaks
caption: "Grandma's kitchen"     <- fine

Use double quotes whenever your text has an apostrophe in it, which in English is constantly.

A bracket that lost its partner. Deleting an item and catching one bracket too many, or too few. Brackets come in pairs the same way tags do.

The habit that makes it stop happening

Add new items in the middle of a list, not at the end.

The last item in a list usually has no comma after it, because nothing follows it. So the end of the list is the one place where copying a neighbouring line gives you the wrong punctuation. Add between two existing items instead and you copy a line that already has its comma in exactly the right place, and the trap cannot fire.

It is a small trick and it will save you this failure for the rest of your life.

10. Check yourself

Your page says <img src="cat.jpg" /> and your file is called Cat.jpg. Does it work?

On your own computer, probably. On the internet, no. Fix it now by renaming the file to cat.jpg, and you will never think about it again.

What are the two parts of <a href="notes.html">Read my notes</a>, and who is each one for?

href="notes.html" is the destination, for the browser. Read my notes is the label, for the person. Change either without touching the other.

Why does every app folder have a file with the same name in it?

Because index.html is the agreed front door. Anything that opens a folder opens that file first without being told to. The folder around it is what keeps the four of them apart.

A picture is missing. What is the least likely cause?

The code. It is the file name or the file’s location nearly every time. Check those two before you change a single line.
