This time the AI interviews you. It asks questions one at a time - who you are, what you want the page to do, what a visitor should walk away knowing - and then, before it builds anything, it stops and tells you exactly which photos it needs and what to name them. Then it builds your page.

You can make this page about you, or about a persona, a pet, a made-up person. Later in the course these pages go on the internet; decide now what you want there, and nobody will ask you to explain the choice.

Everything this chapter has taught you arrives here at once: a folder of its own, an index.html, photos beside it with names that have to match. The difference is that this time the AI tells you the names, about your own photographs, in the middle of a conversation about you.

Find every <img>. How many are there? Does each one’s src="…" match a file in your folder, exactly?

The src is the filename the code is looking for. If the picture shows, they match. If it doesn’t, one character somewhere is different - a capital letter, a space, .jpeg instead of .jpg.

Find the first <a href="…">. Where does it go?

Whatever is inside the quotes after href= is where it goes; the words between the tags are what gets clicked. The same two parts as the recipe notes page. If yours points at another website the quotes will hold a full address starting with https://; if it points at a page of your own it will just be a file name, because that file is beside this one.

Find <style>. Roughly how long is it compared to everything else?

Usually longer than the rest of the file put together. Looks are most of the code. You’ll almost never write it and you’ll rarely need to touch it - the AI is good at this part.

Change one heading - the words between an <h1> or <h2> pair. Save, refresh. Then change the tab title in <title>. Two edits you trust.

If your page has a list - hobbies, links, anything in <li> tags - add one more item by copying an existing <li>…</li> line and changing the words. Same move as adding a picture to the captions list, in HTML this time instead of JavaScript.

A photo shows a broken-image icon

It’s the filename, ninety-nine times in a hundred. Right-click the broken image → Inspect. The highlighted line has src="…" - that’s what the code expects. Compare it to the actual file on disk, character by character: capital letters, spaces, .jpg versus .jpeg versus .JPG. Fix whichever one is wrong. Also check the photo is in my-page, not still in Downloads or Photos.

My photo is a .HEIC file and won’t show

iPhones save photos as HEIC, and browsers mostly can’t show that format. Export or convert it to JPG first (on a Mac, open it in Preview → File → Export → JPEG; on iPhone, Settings → Camera → Formats → Most Compatible for future photos). Then name the JPG exactly what the code expects.

The AI built the page without asking about images

Tell it: “Stop. Before the page, list exactly which images you need, what to name them, and where to put them.” Then continue. Making the AI slow down is a skill, not a failure.

The page looks nothing like I imagined

That’s normal for a first build, and it’s what Grow it is for. Describe what’s off in plain words - “the photo is too big,” “make the colors calmer,” “put the links at the top” - one change at a time. Each one is an iteration, and iterations are the normal mode.
