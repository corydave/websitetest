B

<body> … </body>

Everything a visitor can see: headings, paragraphs, buttons, images, links. The <script> usually sits at the very end of the body.

<br />

A line break: end the line here, inside a paragraph. For the lines of an address, a poem, an ingredient list. It has no closing tag, because nothing goes inside a line break; instead the slash goes at the end. Two in a row make a blank line. But for a new thought, use <p>, not a pile of <br />s.

Browser

The program that reads web page files and draws them on your screen: Chrome, Safari, Edge, Firefox. It reads the file top to bottom and follows the instructions in it. When you double-click an .html file, this is what opens.

<button> … </button>

A thing to press. The words between the tags are its label. What the button says is HTML; what it does is JavaScript, somewhere in the script.

C

Comment

A note in the code that the browser skips completely. For people, not machines. In HTML: <!-- like this -->. In JavaScript: a line starting with //. The AI writes lots of them, one above nearly every block, saying what the block does in plain language. They are the first place to look when you want to change something.

Content

The words between a pair of tags - the part that actually shows on the page. In <h1>Hello, world</h1>, the content is Hello, world. Changing content is always safe; you cannot break a page by changing the words between two tags.

CSS

The language that says what a page looks like: colors, sizes, fonts, spacing. It lives inside the <style> tag. In this course the AI writes almost all of it; you will learn to find the one line you want to change.

D

Definition of Done

The one sentence on every lab that says what finished looks like. If your app does that, the lab is done. Everything else in the lab is a bonus.

Developer Console

A panel built into every browser that shows what went wrong and where. Open it with F12, or right-click the page and choose Inspect, then the Console tab. A red line is an error: it has a message and a line number. Copy the red line exactly and paste it to the AI. Most students do not know this panel exists; now you do.

<!DOCTYPE html>

The very first line of every page. It tells the browser this is a modern web page. It is not really a tag and it never closes. It is always there and you never think about it.

F

File extension

The last part of a file's name, after the dot: .html, .jpg, .txt. It tells the computer what kind of file it is. Mac and Windows hide extensions by default, so a file that looks like qr-code.html can secretly be qr-code.html.txt and show a blank page. Turning extensions on is the first thing this course asks you to do.

H

<h1> … </h1>

The biggest heading on a page. <h2> through <h6> are smaller headings, in order. Changing the words between the tags is the safest edit you can make.

Hand edit

A change you make to the code yourself, in the editor, without asking the AI. This course builds up to them slowly: first the words between two tags (safe; you cannot break anything), then a number the code uses, then a date with a strict format.

<head> … </head>

The settings section of a page. Nothing inside the head shows on the page itself. It holds the <title> (the browser tab's text) and the <style> (how things look). Head or body? If a visitor can see it, it is in the body; if it is a setting, it is in the head.

HTML

The language that says what is on a page. It is mostly your own words, wrapped in tags that say what each thing is: a heading, a paragraph, a button. Stands for HyperText Markup Language, which you will never need to say out loud.

<html> … </html>

The outermost pair of bookends. Everything on the page sits between <html> near the top and </html> on the last line.

I

Iteration

Asking for a change to something that already works, then another, then another. Add a color picker. Now put my initials in the middle. Small asks, one at a time, is the normal way to build; nobody gets the whole thing in one prompt.

J

JavaScript

The language that makes a page do things: count down, flip a card, respond to a click. It lives inside the <script> tag. Not related to Java, despite the name.

K

“Keep everything else the same”

The sentence to put at the end of an ask for one change. Left alone, an AI asked to change one thing will sometimes redesign three, or quietly drop a feature you added earlier. Saying what not to touch is part of asking well.

L

Library

Someone else's code that your page borrows, usually with one line like <script src="https://…">. The QR code generator borrows a library that knows how to draw QR codes; nobody writes that part themselves. It is also why some pages need the internet even though they are files on your computer.

M

Milliseconds

Thousandths of a second. JavaScript measures time in them, so 1000 means one second and 60000 means one minute. When you see a suspiciously large number next to a timer, it is probably milliseconds.

N

NaN

“Not a Number.” What the browser says when it was asked to do math on something that is not a number - most often a date typed in a form it did not understand. If you just edited a date and see this, look at what you changed: a month over 12, a missing dash, a lost quote. Fix that one thing.

Nesting

Tags inside tags, like boxes inside boxes. A paragraph sits inside the body; a bit of bold sits inside the paragraph. The rule: whatever you open last, you close first.

<p>Some <strong>bold</strong> words</p>

O

Opening and closing tags (bookends)

The two halves of a tag pair. The opening tag says start: <p>. The closing tag is the same word with a slash in front and says stop: </p>. Whatever sits between the bookends is the content. Forget the closing tag and everything after it gets swept in - a whole page turns into one giant heading.

P

<p> … </p>

A paragraph. Every paragraph gets its own pair. The browser adds a little space above and below each one, so two paragraphs look like two paragraphs. Without the tags, the words run together into one lump.

Paste over everything

Replacing the whole file with the AI's new version: in your editor, select all (Ctrl+A, Mac ⌘+A), then paste. Not adding the new code below the old - replacing it. Half-pasted files are a common cause of a blank page.

Plain text

Text with nothing hidden in it: no fonts, no bold, no invisible formatting. Code has to be plain text. Word, Google Docs, TextEdit, and Notepad all add or mangle things, which is why you need a plain-text editor like TXTEDTR.

Prompt

What you type to the AI: a description of what you want, in your own words, like you are explaining it to a friend. Say what goes in, what comes out, and what it should look like. Then paste the specification after it.

S

Save As

Saving a file under a name and location you choose. In this course you type the whole name yourself, including the .html, and pick the vibe-coding folder on purpose. Plain Save writes over the file you already have; Save As makes a new one.

Save, then refresh

The two-step loop for seeing a change. Save the file in your editor, then refresh the browser tab (the circular arrow, or F5, or ⌘+R) so it reads the file again. If nothing changed, you skipped one of the two. This is the first thing to check, every time.

Screenshot

A picture of your screen. Mac: Shift+⌘+4, then drag a box. Windows: Win+Shift+S. Chromebook: Shift+Ctrl+Show windows. You will use it for hand-ins and for showing someone exactly what went wrong.

<script> … </script>

Where the behavior lives: the JavaScript that makes a page count down, flip a card, or make a QR code. Usually at the end of the body. When something moves or responds, this is where it happens.

Self-closing tag

A tag that is complete on its own, with no closing partner, because nothing goes inside it. The slash goes at the end: <br />. You will meet <img … /> next chapter - an image has nothing inside it either.

setInterval

The line of JavaScript that makes a page tick: run this again every so many milliseconds. setInterval(update, 1000) means run update once a second. It is the reason a countdown counts and a timer times. You will recognize it in every app that moves.

Specification (the spec)

The block of rules you paste at the end of every prompt. It tells the AI how to build things for this course: one file, plain comments, works on a phone, and so on. You are not expected to understand every line yet; one line gets explained per chapter.

<strong> and <em>

Bold and emphasis (usually italic), wrapped around a few words inside a paragraph: <p>This is <strong>important</strong>.</p>

<style> … </style>

Where the looks live: colors, fonts, sizes, spacing. It sits in the head and is written in CSS. Usually the longest part of a file, and the part you will change least by hand.

T

Tag

A word in angle brackets that tells the browser what something is: <h1> means a big heading, <p> means a paragraph. Most tags come in pairs, like bookends, with your content between them:

<h1>Hello, world</h1>

The tags never show on the page. Only the words between them do.

The Copy button

The small button in the corner of a code block in the AI's reply. It copies the whole block, exactly. Always use it instead of selecting the code by hand, which misses the top or bottom line more often than you would think.

The six landmarks

The six tags every page in this course has, in the same arrangement: <html> around everything; <head> for settings, holding <title> and <style>; and <body> for everything you see, with <script> usually at its end. Learn them as a map. A 300-line file becomes three rooms to look in.

<title> … </title>

The page's name. It lives in the head and shows on the browser tab, not on the page. It is the easiest hand edit there is: change the words between the tags, save, refresh, look at the tab.

<title>Dave's Focus Timer</title>

TXTEDTR

The plain-text editor we use in this course, at txtedtr.app. It is one HTML file, built with AI, by your instructor - the same kind of thing you are making. Notepad++, VS Code, or Sublime Text work too. What does not work: Word, Google Docs, TextEdit, Notepad.

V

Value

A fact the code uses: the 25 in a Pomodoro timer, the date in a countdown. Values often sit near the top of the script so you can find them. Changing a value changes how the whole app behaves, which is why it is a step up from changing words.

Version copy

A duplicate of a working file, made before you let the AI change it: pomodoro.html becomes pomodoro-v1.html. The plain name is always the current version; the numbered copies are the history. If an iteration breaks things, the copy is your way back.

Vibe coding

Building software by describing what you want to an AI in plain language, running what it gives you, and asking for changes until it is right. You steer; the AI types. The loop is: ask, copy, paste over, save, refresh.

W

Web page

A text file that a browser knows how to read and draw. The file describes what is on the page (words, headings, buttons) and how it should look and behave. Every page you have ever visited is one of these, no matter how fancy.

Whitespace

Spaces, tabs, and new lines. The browser squashes any amount of it down to one space, so pressing Enter in the code does nothing and ten spaces look like one. All that neat indentation in the AI's code is for you, so you can see what is inside what. The browser ignores it.

Every demo on this page runs right here, in your browser. Nothing you type is sent anywhere.
