%

%20 (URL encoding)

Web addresses cannot contain spaces, so a space is written as %20. Other awkward characters get codes too. You can type a normal space in the address bar and the browser swaps it in for you; a well-made page turns it back into a space.

<

<a>

The link tag. It has two separate parts: href, which says where it goes and is for the browser, and the words between the tags, which are what a person sees and clicks. Change either without touching the other.

activeTab

A permission that gives an extension access to the tab you are looking at only once you click it, and takes it away again afterwards. It is the polite version: the extension can do nothing at all until you ask, which is why a tool built on it shows a much gentler sentence on its card.

alt text

Short for alternative. Words that stand in for a picture. A screen reader says them out loud to someone who cannot see the image, they appear on the page if the file is missing, and search engines read them. Write them like you are describing the picture to someone over the phone - not photo or image1.

<fieldset> and <legend>

How you name a group of form controls, usually radio buttons. Without it a person hears "Morning, radio button, one of three" and has no idea what question they are answering.

<fieldset>
  <legend>Which session?</legend>
  ...the radio buttons...
</fieldset>

href

The attribute on a link that says where the link goes. When the destination is a file sitting beside this one, it is just the file name: href="notes.html".

<img />

The tag that puts a picture on a page. It has nothing to wrap, so it closes itself instead of coming in a pair. It needs two attributes: src for which file, and alt for what the picture shows.

index.html

The front door of a folder. Every app you build gets a folder, and the main page inside it is called index.html. The name is a convention everything agrees on: browsers and web servers open that file first, without being told to. Four folders can each hold a file with this name without any confusion, because the folder is what tells them apart.

<label>

The visible text that says what a form field is for, tied to the field with for and the field's id:

<label for="email">Your email</label>
<input id="email" type="email">

A properly connected label is announced with the field, and clicking it focuses the field, which makes it easier to hit.

localStorage

A small box the browser gives a page to keep things in, which survives closing the tab. You put something in under a name and get it back later by that name. It is the simplest way to make an app remember.

Two limits worth knowing now: it is this browser on this computer - nothing syncs to your phone - and anyone using that computer can read it.

manifest.json

The note on the front of an extension's folder. Every extension has exactly one, named exactly this. It says what the extension is called, what it wants to touch, and which file does the work:

{
  "manifest_version": 3,
  "name": "My Launch Pad",
  "version": "1.0",
  "chrome_url_overrides": { "newtab": "newtab.html" }
}

It is written in JSON, not JavaScript, which matters more than it sounds.

src

Short for source. The attribute that names the file to fetch. On a picture it is the file name of the picture, and the browser looks for it in the same folder as the page.

SyntaxError

The Developer Console saying: I cannot read this, so I stopped. Usually punctuation - a missing comma, an apostrophe inside single quotes, a stray bracket. The message comes with a line number, and the problem is on that line or just above it.

A

Accessibility

Building so that people can actually use the thing - including somebody using a keyboard with no mouse, somebody who cannot see colors the way you do, somebody whose hands shake, and somebody whose computer reads the screen aloud.

Not a checklist you run at the end. Almost everything on the list makes the app better for everybody: clearer labels, visible focus, information that does not depend on one sense.

Accessible name

What assistive technology calls something. It comes from a label, an aria-label, alt text, or the words inside the element - and when there is none, a control is announced as just "button" or "text box", which tells the person nothing at all.

You can see it for any element in Developer Tools: Elements panel, then the Accessibility tab in the sidebar.

ARIA

Extra attributes that tell assistive technology things plain HTML cannot express. Genuinely useful, and the most misused thing on the web, because people reach for it instead of just using the right tag.

The rule people say out loud is the first rule of ARIA is don't use ARIA. If real HTML can do the job, use real HTML.

Assistive technology

Anything somebody uses to work a computer differently: screen readers, magnifiers, voice control, switches, high-contrast modes. It is far more common than people expect, and most of it is already built into the computer rather than bought separately.

Attribute

Extra information carried inside an opening tag, always in the shape name="value". A picture tag needs to know which picture; a link tag needs to know where it goes. The quotes are part of it, not decoration.

<img src="photo.jpg" alt="A bowl of soup" />

B

<body> … </body>

Everything a visitor can see: headings, paragraphs, buttons, images, links. The <script> usually sits at the very end of the body.

<br />

A line break: end the line here, inside a paragraph. For the lines of an address, a poem, an ingredient list. It has no closing tag, because nothing goes inside a line break; instead the slash goes at the end. Two in a row make a blank line. But for a new thought, use <p>, not a pile of <br />s.

3325 Marvin Sands Drive<br />
Canandaigua, NY 14424

Broken picture icon

The little torn-page symbol, or an empty box with the alt words in it. It means one thing: the browser looked in this folder for that name and did not find it. Check the folder, then the spelling, then the format - almost never the code.

Browser

The program that reads web page files and draws them on your screen: Chrome, Safari, Edge, Firefox. It reads the file top to bottom and follows the instructions in it. When you double-click an .html file, this is what opens.

Browser extension

A small program that adds something to your browser, or changes pages you visit. It is not a web page and it is not an app you install on your computer: it is a folder of ordinary HTML, CSS and JavaScript, with one extra file on the front telling Chrome what it is allowed to do.

The ad blockers, password managers and dark-mode buttons people install are all this shape.

<button> … </button>

A thing to press. The words between the tags are its label. What the button says is HTML; what it does is JavaScript, somewhere in the script.

C

Caption

Words shown with a picture, saying what it is. Different from alt text: a caption is for everybody and appears on the page, while alt is for people who cannot see the picture and normally stays invisible. A picture often wants both.

Card

A box holding one thing - a picture, a heading, a couple of lines. Usually with rounded corners, a soft shadow and space around the edge. It is one of the most useful words you can say to an AI, because it is the word the people who build these things use.

CDN

Short for content delivery network: a company that keeps copies of popular libraries on computers all over the world, so a page can fetch one quickly wherever it is opened. The two big free ones are cdnjs and jsDelivr.

A library address reads like a label: who is handing it over, which library, which version, which file.

cdnjs.cloudflare.com/ajax/libs/qrcodejs/1.0.0/qrcode.min.js

Chrome Web Store

Where extensions normally come from. Putting one there costs a one-off developer fee and means waiting in a review queue, which is why most people's own tools never go in it. Extensions cannot run on the Web Store's own pages, so it is a bad place to test yours.

Color as the only signal

When the only difference between two states is their color - red for wrong and green for right, a yellow tile and a green tile. For a lot of people there is then no difference at all.

The fix is never to stop using color. It is to add a second signal: a symbol, a word, a border, a position. Color then becomes the fast way to read it rather than the only way.

Colorblindness

Seeing some colors as closer together than most people do. Around one man in twelve has some form of it. Deuteranopia is the most common, and it pulls green towards gray - which is why a green "correct" tile and a gray "wrong" tile can end up looking almost identical.

Chrome can show you: Developer Tools, then the Rendering drawer, then Emulate vision deficiencies.

Comma

The separator between one item in a list and the next. Leave one out and the browser cannot make sense of the list, stops reading, and shows you a blank page - which feels wildly out of proportion to a missing comma, and is. Add new items in the middle of a list rather than at the end and the problem never comes up.

Comment

A note in the code that the browser skips completely. For people, not machines. In HTML: <!-- like this -->. In JavaScript: a line starting with //. The AI writes lots of them, one above nearly every block, saying what the block does in plain language. They are the first place to look when you want to change something.

Content

The words between a pair of tags - the part that actually shows on the page. In <h1>Hello, world</h1>, the content is Hello, world. Changing content is always safe; you cannot break a page by changing the words between two tags.

Content script

A JavaScript file that Chrome drops into a page somebody else wrote, where it can read and change anything on it. This is the part of an extension that does the surprising stuff: rewriting words, hiding adverts, rearranging a page you use every day.

Change one and you need two reloads: the extension first, then the page.

Context menu

The menu you get when you right-click. An extension can add its own items to it, and can say only show this when the person right-clicks something they can type into. Because the thing you right-clicked is the thing you meant, it avoids the problem popups have.

Contrast ratio

How different two colors are, written like 4.5:1. Normal text usually needs at least 4.5 to 1 against its background; large text can go down to 3 to 1.

Pale gray on white is the classic failure. It looks elegant on a good monitor in a dark room and disappears on a phone outdoors.

CSS

The language that says what a page looks like: colors, sizes, fonts, spacing. It lives inside the <style> tag. In this course the AI writes almost all of it; you will learn to find the one line you want to change.

CSV

Comma-separated values: a spreadsheet saved as plain text, one row per line, with commas between the columns. Every spreadsheet program can open and save it, which makes it the easiest way to move data between programs.

Month,Tacos,Burritos
January,420,310
February,388,295

D

Dashboard

A screen that shows what a pile of numbers means at a glance: a few big numbers at the top, charts underneath. The spreadsheet holds the data; the dashboard tells the story.

Definition of Done

The one sentence on every lab that says what finished looks like. If your app does that, the lab is done. Everything else in the lab is a bonus.

Dependency

A library your app cannot work without. Take the line away and the app breaks. Every library you borrow is a dependency, and every dependency is something you are trusting.

Developer Console

A panel built into every browser that shows what went wrong and where. Open it with F12, or right-click the page and choose Inspect, then the Console tab. A red line is an error: it has a message and a line number. Copy the red line exactly and paste it to the AI. Most students do not know this panel exists; now you do.

Developer mode

A switch at the top right of chrome://extensions. With it on, you can load an extension from a folder on your own computer instead of installing one from the Chrome Web Store. Some school and work computers block it by policy, and when they do there is no way around it from inside the browser.

<!DOCTYPE html>

The very first line of every page. It tells the browser this is a modern web page. It is not really a tag and it never closes. It is always there and you never think about it.

E

Edge case

An input nobody planned for until somebody typed it: a blank option, the same thing twice, a name with a comma in it. Trying them on purpose is half of testing anything.

Empty state

What an app shows when there is nothing to show yet - an empty list, a missing name. A friendly message like Add at least two options first makes an app feel finished; a blank screen makes it feel broken. The AI often forgets it unless you ask.

F

File extension

The last part of a file's name, after the dot: .html, .jpg, .txt. It tells the computer what kind of file it is. Mac and Windows hide extensions by default, so a file that looks like qr-code.html can secretly be qr-code.html.txt and show a blank page. Turning extensions on is the first thing this course asks you to do.

Focus

Where the keyboard currently is. Press Tab and focus moves to the next thing you can interact with. If something cannot take focus, a keyboard user cannot reach it, and for a lot of people that means it does not exist.

Focus ring

The outline a browser draws around whatever has focus. Browsers put it there for free and it is the only way a keyboard user can see where they are.

Removing it because it looks untidy is the single most common accessibility mistake on the web, and it is usually one line: outline: none. If you take it away, replace it with something clearer. Never just take it away.

Fork

A copy of somebody's project that other people carry on working on separately. When a popular library stops being looked after, a fork is often how it keeps going.

G

Game loop

The heartbeat of every game: a few lines that run about sixty times a second. Each time, they move things a little, check what touched what, and draw the new picture. Everything that seems to happen continuously in a game is really this loop running very fast.

H

<h1> … </h1>

The biggest heading on a page. <h2> through <h6> are smaller headings, in order. Changing the words between the tags is the safest edit you can make.

Hand edit

A change you make to the code yourself, in the editor, without asking the AI. This course builds up to them slowly: first the words between two tags (safe; you cannot break anything), then a number the code uses, then a date with a strict format.

<head> … </head>

The settings section of a page. Nothing inside the head shows on the page itself. It holds the <title> (the browser tab's text) and the <style> (how things look). Head or body? If a visitor can see it, it is in the body; if it is a setting, it is in the head.

HEIC

The format iPhones save photos in. Browsers mostly cannot show it, and renaming the file to .jpg does not help - the inside of the file has to be converted, not just the name. Export it as a JPG first.

Host permission

Permission to work on particular websites, named in the manifest, whether or not you have asked the extension to do anything. Broader and longer-lasting than activeTab, and the thing to ask for only when the extension genuinely has to run on its own.

HTML

The language that says what is on a page. It is mostly your own words, wrapped in tags that say what each thing is: a heading, a paragraph, a button. Stands for HyperText Markup Language, which you will never need to say out loud.

<html> … </html>

The outermost pair of bookends. Everything on the page sits between <html> near the top and </html> on the last line.

I

Inspect

Right-click anything on a page and choose Inspect to see the exact line of code behind it, highlighted. The fastest way to find out what file name a broken picture is actually asking for.

Invented libraries (slopsquatting)

AI tools sometimes suggest a library that does not exist, and they tend to invent the same names repeatedly. Anyone can then publish a real library under that invented name, with whatever code they like inside. Checking that a library is real before you use it is the whole defense.

Iteration

Asking for a change to something that already works, then another, then another. Add a color picker. Now put my initials in the middle. Small asks, one at a time, is the normal way to build; nobody gets the whole thing in one prompt.

J

JavaScript

The language that makes a page do things: count down, flip a card, respond to a click. It lives inside the <script> tag. Not related to Java, despite the name.

JPG and JPEG

The same kind of picture file under two spellings, for historical reasons nobody enjoys. It does not matter which one your file uses, but the code has to say the same one the file does.

JSON

A way of writing down information so a program can read it. It looks almost exactly like JavaScript and follows stricter rules: no comments, no comma after the last item, and double quotes only. Break one of those in a manifest.json and Chrome refuses the whole extension rather than loading a broken one.

If you are unsure, paste it into the AI and ask "is this valid JSON?"

K

“Keep everything else the same”

The sentence to put at the end of an ask for one change. Left alone, an AI asked to change one thing will sometimes redesign three, or quietly drop a feature you added earlier. Saying what not to touch is part of asking well.

Key and value

A way of storing things so you can find them again: the value is what you saved, and the key is the name you saved it under. Using a page's web address as the key is what lets one notes app keep a separate note for every page you visit.

Same idea as naming your files properly. The name is how you find the thing.

L

Least privilege

Asking for the smallest amount of access that will do the job, and no more. The same instinct as not handing a house key to somebody who only needs to water the plants once. It is a habit worth building now, because the consequences get much larger in the chapters about keys and servers.

Library

Someone else's code that your page borrows, usually with one line like <script src="https://…">. The QR code generator borrows a library that knows how to draw QR codes; nobody writes that part themselves. It is also why some pages need the internet even though they are files on your computer.

Lighthouse

An audit built into Chrome's Developer Tools. Tick Accessibility, click Analyze, and you get a score out of 100 plus a list of what is wrong and which elements are wrong, in plain words.

It only runs on a real web address, not a file from your computer. And a score of 100 is not a certificate - it checks what a machine can check, which is not everything.

ListenMode

A small tool built for this course. It hides the page and says out loud what the keyboard lands on as you press Tab - "Submit, button", or revealingly, "button, with no name".

It is a demonstration, not a screen reader. A real one reads your whole computer, has browse and focus modes and hundreds of commands. ListenMode does one slice. Enough to find holes in your own work; not enough to tell you what using a screen reader is really like.

Live region (aria-live)

The one piece of ARIA this course asks you to use. When something changes on the page by itself - a result appears, a score updates, an error shows - nothing announces it, because no HTML tag means say this out loud when it changes.

<p id="status" aria-live="polite"></p>

Put text in that paragraph and a screen reader reads it. The element has to be on the page before the text changes, or nothing is announced.

Load unpacked

The button that turns a folder on your computer into a working extension. Pick the folder that contains manifest.json - not the manifest file itself, and not the folder above it.

Chrome remembers where that folder is, not what is in it. Move or rename it and the extension stops working.

M

Maintained

A library somebody is still looking after: fixing problems, answering questions, releasing new versions. You can tell by when its files were last changed on GitHub. An unmaintained library still works; it just means nobody is coming to fix it if a problem turns up.

Match pattern

The line in a manifest that says which websites a content script runs on. A single site looks like https://en.wikipedia.org/*, where the * means "any page on it". The widest possible is <all_urls>, which means every page you ever open.

It is fussy about exact addresses: en.wikipedia.org is not simple.wikipedia.org.

Milliseconds

Thousandths of a second. JavaScript measures time in them, so 1000 means one second and 60000 means one minute. When you see a suspiciously large number next to a timer, it is probably milliseconds.

Minified

Code squashed onto as few lines as possible, with the spaces and comments removed, so it downloads faster. The .min in qrcode.min.js means minified. It is for computers, not for reading.

Model (trained)

A file full of numbers that a computer adjusted over and over, while looking at huge numbers of examples, until it got good at one job - finding faces, say, or predicting the next word. Nobody writes a model line by line; it is trained.

The AI you prompt is a very large model. The one in the googly eyes lab is a tiny one that only knows faces, and it runs right on your computer.

N

NaN

“Not a Number.” What the browser says when it was asked to do math on something that is not a number - most often a date typed in a form it did not understand. If you just edited a date and see this, look at what you changed: a month over 12, a missing dash, a lost quote. Fix that one thing.

Nesting

Tags inside tags, like boxes inside boxes. A paragraph sits inside the body; a bit of bold sits inside the paragraph. The rule: whatever you open last, you close first.

<p>Some <strong>bold</strong> words</p>

O

Official source

The library's own website, run by the people who wrote it. Big CDNs keep copies, and copies can fall behind. When in doubt, get the line from the official source, not from the AI.

Opening and closing tags (bookends)

The two halves of a tag pair. The opening tag says start: <p>. The closing tag is the same word with a slash in front and says stop: </p>. Whatever sits between the bookends is the content. Forget the closing tag and everything after it gets swept in - a whole page turns into one giant heading.

P

<p> … </p>

A paragraph. Every paragraph gets its own pair. The browser adds a little space above and below each one, so two paragraphs look like two paragraphs. Without the tags, the words run together into one lump.

Paste over everything

Replacing the whole file with the AI's new version: in your editor, select all (Ctrl+A, Mac ⌘+A), then paste. Not adding the new code below the old - replacing it. Half-pasted files are a common cause of a blank page.

Permission

Something an extension asks to be allowed to do, listed in its manifest and shown to you before you install it. "Read and change all your data on all websites" is the big one, and it means exactly what it says: while that extension is on, it can see anything on any page you open, including things you are typing.

Pinning a version

Putting an exact version number in a library's address, so your page always gets that same version. An address that says latest, or leaves the number out, quietly gets whatever is newest the day the page opens - which is how an app breaks without you changing anything.

Placeholder is not a label

Faint gray text inside a box is not a label. It vanishes the moment you type, so anybody who loses their place has nothing to go back to; it usually fails contrast; and it may not be announced at all. Use a real <label> that stays on the page, and keep the placeholder for an example if you want one.

Plain text

Text with nothing hidden in it: no fonts, no bold, no invisible formatting. Code has to be plain text. Word, Google Docs, TextEdit, and Notepad all add or mangle things, which is why you need a plain-text editor like TXTEDTR.

Popup

The small panel that appears when you click an extension's icon. It is an ordinary little web page. One catch worth knowing: opening it takes the cursor out of whatever box you were typing in, so a popup that inserts text into a page needs extra work that a right-click menu does not.

Prompt

What you type to the AI: a description of what you want, in your own words, like you are explaining it to a friend. Say what goes in, what comes out, and what it should look like. Then paste the specification after it.

Q

Query string

The part of a web address after the ?. It carries information for the page to read, as names and values joined by &:

invite/?to=Sam&event=Game%20Night

Each name=value piece is called a URL parameter. Anyone who has the link can read it, so never put anything private in one.

R

Reduced motion

Some people get genuinely unwell from things moving on screen, and their computer already knows they have asked for less of it. prefers-reduced-motion is how your page finds out, so you can shorten or switch off animations without being asked.

S

Save As

Saving a file under a name and location you choose. In this course you type the whole name yourself, including the .html, and pick the vibe-coding folder on purpose. Plain Save writes over the file you already have; Save As makes a new one.

Save, then refresh

The two-step loop for seeing a change. Save the file in your editor, then refresh the browser tab (the circular arrow, or F5, or ⌘+R) so it reads the file again. If nothing changed, you skipped one of the two. This is the first thing to check, every time.

Screen reader

Software that reads what is on screen out loud and lets you move around with the keyboard. It does not read your HTML; it reads what the browser worked out your HTML means, which is why the tags you choose matter so much.

Built in everywhere: VoiceOver on a Mac (Cmd+F5), Narrator on Windows (Ctrl+Windows+Enter), ChromeVox on a Chromebook (Ctrl+Alt+Z). Write the off switch down before you turn one on.

Screenshot

A picture of your screen. Mac: Shift+⌘+4, then drag a box. Windows: Win+Shift+S. Chromebook: Shift+Ctrl+Show windows. You will use it for hand-ins and for showing someone exactly what went wrong.

<script> … </script>

Where the behavior lives: the JavaScript that makes a page count down, flip a card, or make a QR code. Usually at the end of the body. When something moves or responds, this is where it happens.

Self-closing tag

A tag that is complete on its own, with no closing partner, because nothing goes inside it. The slash goes at the end: <br />. You will meet <img … /> next chapter - an image has nothing inside it either.

Semantic HTML

Using the tag that means the thing. A <button> for a button, an <a> for a link, a <label> for a label, real headings in order.

The highest-leverage thing in this chapter. A real button is focusable, works with Enter and Space, and announces itself as a button, all for free. A <div> painted to look like one does none of that until you add it back by hand, and you will miss some.

Service worker

A small file in an extension that runs in the background, outside any page. It is for jobs that are about the browser rather than about a web page: building a right-click menu, or deciding what the toolbar icon does. Often three lines long, and it has to be its own file.

setInterval

The line of JavaScript that makes a page tick: run this again every so many milliseconds. setInterval(update, 1000) means run update once a second. It is the reason a countdown counts and a timer times. You will recognize it in every app that moves.

Side panel

A strip that opens down the side of the browser and stays there while you scroll, click links and move around. Unlike a popup, it does not close the moment you look away, which makes it the right shape for anything you want beside a page rather than on top of it.

Site access

What an extension is allowed to reach right now, which is not the same as what it asked for when you installed it. Right-click any extension's icon in the toolbar and you can change it to On click or On specific sites without uninstalling anything.

Most extensions work perfectly well on On click, and almost nobody tries.

Slider

A row of cards shown one at a time, with a way to move between them. Also called a carousel. Asking for "a slider of cards" gets you what you pictured; asking for "make the pictures go sideways" gets you a guess.

Specification (the spec)

The block of rules you paste at the end of every prompt. It tells the AI how to build things for this course: one file, plain comments, works on a phone, and so on. You are not expected to understand every line yet; one line gets explained per chapter.

<strong> and <em>

Bold and emphasis (usually italic), wrapped around a few words inside a paragraph: <p>This is <strong>important</strong>.</p>

<style> … </style>

Where the looks live: colors, fonts, sizes, spacing. It sits in the head and is written in CSS. Usually the longest part of a file, and the part you will change least by hand.

Supply chain attack

An attack that comes in through something you borrowed rather than something you built. In 2024, the address of a library called polyfill.io changed hands, and the new owner sent harmful code to visitors of more than a hundred thousand websites that had trusted it for years. None of those sites changed a thing.

T

Tab order

The order Tab visits things in. By default it follows the order of your HTML, which is one more reason to write the page in the order it should be read. If the tab order jumps around the screen at random, something is reordering things with CSS and the markup no longer matches what people see.

Tag

A word in angle brackets that tells the browser what something is: <h1> means a big heading, <p> means a paragraph. Most tags come in pairs, like bookends, with your content between them:

<h1>Hello, world</h1>

The tags never show on the page. Only the words between them do.

Telling is not checking

You asked the AI for something. It said yes. Those are two different facts, and only one of them is evidence.

The biggest idea in this course, and it is not really about accessibility - it is about every instruction you will ever give an AI. The output looking right is not the same as the output being right, and the only way to close that gap is to go and look.

Text node

One run of readable text on a page, with no tags inside it. Code that wants to change words goes looking for text nodes rather than rewriting the whole page, because the whole page includes tags, web addresses and the page's own code - and rewriting those breaks it.

A phrase split over two lines in the source is two things to the computer, which is why some matches quietly fail.

The Accessibility tab

In Developer Tools: the Elements panel, then the sidebar on the right where Styles and Computed live. It is usually hidden behind the small ≫ button at the end of that row, which is why almost nobody finds it. It shows what the selected element is called and what it counts as.

Easier route: press Ctrl+Shift+P (Cmd+Shift+P on a Mac) with Developer Tools open and type what you want.

The background check

Four questions to ask about any library before you trust it:

  1. Is it real?
  2. Where is it coming from?
  3. Is anybody still looking after it?
  4. Is this the newest version?

Old is not the same as bad. Old and doing something risky is the thing to watch.

The Copy button

The small button in the corner of a code block in the AI's reply. It copies the whole block, exactly. Always use it instead of selecting the code by hand, which misses the top or bottom line more often than you would think.

The same-folder rule

When a page asks for another file by name - a picture, a second page - the browser looks in the folder the page is in. Just there, nowhere else. So everything an app needs sits beside the app: one folder, one address, and a name is enough to find anything at it.

The six landmarks

The six tags every page in this course has, in the same arrangement: <html> around everything; <head> for settings, holding <title> and <style>; and <body> for everything you see, with <script> usually at its end. Learn them as a map. A 300-line file becomes three rooms to look in.

<title> … </title>

The page's name. It lives in the head and shows on the browser tab, not on the page. It is the easiest hand edit there is: change the words between the tags, save, refresh, look at the tab.

TXTEDTR

The plain-text editor we use in this course, at txtedtr.app. It is one HTML file, built with AI, by your instructor - the same kind of thing you are making. Notepad++, VS Code, or Sublime Text work too. What does not work: Word, Google Docs, TextEdit, Notepad.

U

Universal design

Designing something so that the widest possible range of people can use it, without anybody needing a special version.

The classic example is not on a screen at all: the dropped kerb at a street corner was put there for wheelchairs, and it is now used by everybody with a stroller, a suitcase, a delivery trolley or a bad knee. Captions were for deaf viewers; now half the world watches with them on in a noisy room.

That is the pattern, and it is why this is not a favor you do for a small group. Big clear buttons, labels that stay put, text you can read in sunlight, something that works without a mouse - every one of those is better for everyone, some of the time, and essential for somebody, all of the time.

Unpacked

An extension running straight from a folder on your machine, rather than installed from the Chrome Web Store. Unpacked means: this computer only, no syncing to your other devices, and no automatic updates. For a tool you built for yourself, all three are fine.

User input

Anything the person using your app types, taps or chooses while it is running. The Decision Maker's options are user input. The Magic 8-Ball's answers are not - you wrote those before anyone used it.

V

Value

A fact the code uses: the 25 in a Pomodoro timer, the date in a countdown. Values often sit near the top of the script so you can find them. Changing a value changes how the whole app behaves, which is why it is a step up from changing words.

Version copy

A duplicate of a working file, made before you let the AI change it: pomodoro.html becomes pomodoro-v1.html. The plain name is always the current version; the numbered copies are the history. If an iteration breaks things, the copy is your way back.

Version number

Which release of a library you are getting, usually three numbers like 4.5.1. The first changes when the library changes in a way that might break your app, the second when something new is added, the third for small fixes.

Vibe coding

Building software by describing what you want to an AI in plain language, running what it gives you, and asking for changes until it is right. You steer; the AI types. The loop is: ask, copy, paste over, save, refresh.

W

Web page

A text file that a browser knows how to read and draw. The file describes what is on the page (words, headings, buttons) and how it should look and behave. Every page you have ever visited is one of these, no matter how fancy.

WebAssembly (wasm)

A way to run very fast code inside a web page. Libraries that do heavy work - tracking a face thirty times a second, for instance - often ship that part as .wasm files alongside their JavaScript. The two halves are made to fit each other, so pin them to the same version.

Whitespace

Spaces, tabs, and new lines. The browser squashes any amount of it down to one space, so pressing Enter in the code does nothing and ten spaces look like one. All that neat indentation in the AI's code is for you, so you can see what is inside what. The browser ignores it.
